# FYADR 操作指南

本地运行的 DOCX / TXT 长文档改写工具。所有请求都从本机发出，文档不上传到第三方服务器，只有改写正文会发送给你自己配置的模型接口。

本指南分两部分：**第一部分给使用者**，**第二部分给需要自己重新打包的人**。

---

# 第一部分 · 使用

## 1. 启动

1. 把 `FYADR.exe` 放进**一个单独的文件夹**（例如 `D:\FYADR\`），不要直接扔在桌面或下载目录里。
2. 双击 `FYADR.exe`。
3. 会弹出一个黑色命令行窗口，显示监听地址和已加载的模型连接数量。
4. 浏览器自动打开 `http://127.0.0.1:8765`，就是主界面。

如果浏览器没自动打开，手动访问 `http://127.0.0.1:8765`。

**关闭那个黑色窗口就等于停止服务。** 不关窗口就别关机，否则下次启动会提示端口占用。

第一次启动会在 exe 同级目录生成 `FYADR-data` 文件夹，你的配置、上传的文档、改写结果全在里面。

## 2. 配置模型（第一次必须做）

左侧「模型连接」：

1. 内置了一个 **DeepSeek 官方**入口，点开填 API Key。
2. 点「获取模型」自动拉取可用模型；拉不到就手动填写模型名。
3. 点「验证连接」，返回一句模型回复就算通了。

想用其他服务商（任何 OpenAI 兼容接口）：

- 新建连接，`API 地址` 填到 `/v1` 结尾，例如 `https://api.xxx.com/v1`
- 协议二选一：`Chat Completions` 或 `Responses`，**程序不会自动切换**，选错会直接报错
- 填 Key 和模型名，同样验证一次

密钥只保存在本机 `FYADR-data\config.json` 里，浏览器接口不会返回明文。

## 3. 改写一份文档

| 步骤 | 操作 |
|---|---|
| 1 | 上传 `.docx` / `.txt`，或直接在首页右侧粘贴正文 |
| 2 | DOCX 会先让你**确认正文范围**（TXT 和粘贴的正文跳过这步） |
| 3 | 选模型、改写轮数（1–3 轮）、每轮的提示词 |
| 4 | 设置段内分块档位（细致 / 标准 / 长段）和并发数（1–16） |
| 5 | 开始改写，进度实时更新 |
| 6 | 逐段审阅，然后导出 |

**关于粘贴文字**：不用先把稿子存成文件，把正文粘进首页右侧的输入框就能开始，最多 30 万字。空行分段，同一段里的换行会合并为一段。粘贴的正文默认整篇都算改写范围；要排除标题行或某几段，点文档条右侧的「⋯ → 正文范围」再调。这类文档按 TXT 处理，导出也是 TXT。工作区里想换成新的一段文字，用「⋯ → 粘贴新文本」。

**关于正文范围**：界面会把文档拆成一个个单元，自动锁定这些不该改的部分 —— 标题、表格、目录或自动域、修订痕迹。锁定的部分不参与改写，导出的原文照旧。你可以手动勾选或取消。

**关于审阅**：每段都有原文对照和差异标记，四个动作可选 —— 采用改写、保留原文、手动编辑、重新改写。哪段不满意就单独重跑，不用整篇重来。

**关于导出**：默认按原 DOCX 做原位回填，只替换正文文字节点，字体、字号、行距、编号、页眉页脚、图片、表格都保留原样。文字变长变短可能让 Word 重新换行分页，这不属于格式丢失。

如果导出时提示「内容提醒」或「格式风险」，会列出具体段落，你自己决定返回修改还是继续导出。

## 4. 三个容易误解的地方

**段落隔离 + 段内分块**：每个段落独立处理，不会把不同段落混进同一次请求。超长段落会在句号、问号、分号处继续切分，切分点在建任务时就固定了，所以改写结果能按原顺序拼回去。

**多轮是逐块串行的**：选 2 轮，不是「全篇跑完第一轮再跑第二轮」，而是每个分块依次跑完第 1 轮再跑第 2 轮。不同分块之间才并发。

**提醒不干预**：数字、引用、URL、技术标识符的变化只会被标记出来提醒你，不会覆盖模型结果，也不阻止导出。要不要改，你说了算。

## 5. 数据存放与搬迁

```
FYADR-data\
├─ config.json          模型连接、密钥、提示词方案、偏好
└─ data\
   ├─ documents\        文档骨架与正文范围
   ├─ sources\          原始文件
   ├─ runs\             任务快照、断点、改写结果
   └─ exports\          导出文件
```

- **换电脑 / 备份**：整个 `FYADR-data` 文件夹拷走即可，放到新位置的 exe 旁边就能接着用。
- **恢复出厂**：关掉窗口，删掉 `FYADR-data`，重新启动。
- **从旧版本升级**：如果之前用的是放在 `%APPDATA%\FYADR` 的老版本，第一次以便携方式启动时会自动把旧配置**拷贝**过来（旧目录保持原样，不会被删）。启动横幅会打印一行「已从 … 迁移历史配置」。
- **注意**：`config.json` 里有明文 API Key，别把这个文件夹发给别人。

## 6. 常见问题

**双击被 Windows 拦截 / 提示病毒**
未签名的自打包程序常被 Defender 或 SmartScreen 误报。点「更多信息 → 仍要运行」。如果不放心，用第二部分自己编译一遍。

**提示端口 8765 被占用**
换端口启动：命令行里执行
```
set FYADR_PORT=8899
FYADR.exe
```
然后访问 `http://127.0.0.1:8899`。多半是上次的窗口没关干净，任务管理器里结束 `FYADR.exe` 也行。

**不小心点了两次，开了两个窗口**
不会冲突。第二次启动检测到服务已在运行，会直接帮你打开浏览器然后自己退出。

**验证连接失败**
按顺序排查：Key 是否过期 → API 地址是否少写 `/v1` → 协议是否选错 → 公司网络是否要走代理（程序会读系统代理设置，本地地址自动绕过）。

**改写卡住不动**
某个分块流式返回中断时会暂停该块，不会拿原文冒充结果。点停止后再继续，只会补跑没完成的块。

**想把数据放回系统用户目录**
启动时加参数 `FYADR.exe --appdata`，就会用 `%APPDATA%\FYADR`。

**不想要黑色窗口**
需要自己重新打包，见下方 `console=False`。

# 第二部分 · 自己重新打包

## 1. 环境要求

| 工具 | 版本 |
|---|---|
| Python | 3.10+ |
| Node.js | 18+（含 npm） |
| 系统 | Windows 10 / 11 |

打包只在构建机上需要这些，**发出去的 exe 不需要目标机器装任何东西**。

## 2. 一条命令

仓库根目录双击 `build_exe.bat`，或者：

```
python packaging\build_exe.py
```

脚本依次做四件事：

1. 前端：没装依赖就跑 `npm --prefix app ci`，然后 `npm --prefix app run build` 产出 `app\dist`
2. 建一个 `.venv-build` 虚拟环境，装 `requirements.txt` 和 PyInstaller
3. 调 PyInstaller 按 `packaging\fyadr.spec` 打包
4. 输出 `dist-exe\FYADR.exe`

最后打印体积，单文件约 16 MB。

## 3. 手动分步（想自己控制时）

```bat
npm --prefix app ci
npm --prefix app run build

python -m venv .venv-build
.venv-build\Scripts\activate
pip install -r requirements.txt pyinstaller

pyinstaller --noconfirm --clean --distpath dist-exe --workpath build-temp packaging\fyadr.spec
```

## 4. 打包结构说明

| 文件 | 作用 |
|---|---|
| `packaging\launcher.py` | 程序入口，负责路径纠正、便携目录、单实例、开浏览器、起服务 |
| `packaging\fyadr.spec` | PyInstaller 配置，决定打进哪些文件 |
| `packaging\build_exe.py` | 构建脚本 |
| `build_exe.bat` | 双击入口，只做壳 |

四件套的关系：spec 把 `app\dist` 和 `prompts` 作为数据打包，launcher 负责在运行时把 `core_config` 的路径常量指回解包目录。**这两者缺一不可**，只改一边会出问题。

## 5. 打包原理与三个坑

**前端必须预编译成静态文件。**
上游开发模式是 Vite dev server（1420 端口）+ Flask（8765 端口）两个进程，靠代理串联。单文件 exe 没法带 Node，所以必须 `vite build`。好在 `scripts\web_app.py` 本身支持：只要 `app\dist` 存在，8765 就直接托管界面，SPA 兜底也做了。也就是说打完包是**单端口单进程**。

**坑一：`ROOT_DIR` 在冻结环境下算错。**
`core_config.py` 用 `Path(__file__).resolve().parents[1]` 定位仓库根。打进 PYZ 后 `__file__` 指向 `_MEIPASS`，算出来是解包目录的上一级 —— 于是 `prompts\defaults\classical-rewrite.md` 找不到。更麻烦的是它会**静默降级**：读不到就用一句几十字的兜底文案，程序照样跑，不报任何错，但改写质量直接崩。launcher 在导入前把 `core_config.ROOT_DIR` 改成 `_MEIPASS`，并就地修正 `BUILTIN_TEMPLATE["content"]`。

验证方法：启动后看 `FYADR-data\config.json` 里 `builtin-classical-rewrite` 的 `content` 长度，正常是 **2611 字**。如果只有几十字，说明提示词没打进去。

**坑二：`SPECPATH` 是 spec 文件所在目录，不是仓库根。**
`packaging\fyadr.spec` 里取仓库根要 `os.path.join(SPECPATH, os.pardir)`。写错的表现是 `script '...\packaging\packaging\launcher.py' not found`。

**坑三：新增依赖要显式声明。**
`hiddenimports` 里已经列了 `web_app` 和五个 `core_*` 模块。如果以后加了新的顶层模块，要么写进 `hiddenimports`，要么确保它被上面任何一个模块 import 到。新增静态资源（比如新的提示词目录）要在 `datas` 里加一行。

## 6. 可调项

**去掉黑色控制台窗口**：`packaging\fyadr.spec` 里 `console=True` 改成 `False`。代价是出错看不到信息，进程只能从任务管理器结束。建议分发版保留窗口。

**换图标**：准备一个 `.ico`，在 spec 的 `EXE(...)` 里加 `icon=r"路径\app.ico"`。

**改默认端口**：`launcher.py` 顶部的 `DEFAULT_PORT`。

**改成免解压启动（启动更快、体积更大）**：spec 里把 `EXE` 拆成 `EXE` + `COLLECT` 打目录版，用 `--onedir` 模式。

## 7. 常见构建错误

| 现象 | 原因 |
|---|---|
| `script '...\packaging\packaging\launcher.py' not found` | `SPECPATH` 少退一级 |
| `tsc` 类型报错 | 源码本身没过类型检查，先修代码或临时改成 `vite build` |
| `npm ci` 报锁文件不匹配 | 删掉 `app\package-lock.json` 改用 `npm install`，并同步更新锁文件 |
| exe 起来白屏 | `app\dist` 没打进去，检查 spec 的 `datas` 和 `FRONTEND_DIST` |
| 内置提示词变短 | `prompts` 没打进 `datas`，或 launcher 没做路径纠正 |
| 杀软误报 | 未签名。买代码签名证书，或让用户手动放行 |

## 8. 分发建议

发给别人时打包这几样：

```
FYADR 文件夹\
├─ FYADR.exe
└─ 操作指南.md        （本文件）
```

**不要**把 `FYADR-data` 一起发出去 —— 那里面有你的 API Key 和文档。
